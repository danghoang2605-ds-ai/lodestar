Why I built this

A tool I needed, so I built it.

I am an international student. Most scholarship lists are not written with people like me in mind, so I made one that is.

The problem

When I started looking for ways to pay for school in the United States, I hit the same wall over and over. A lot of scholarships quietly require citizenship or a green card. The ones that stay open to international students are real, but they sit scattered across dozens of sites, each with its own form, its own essay, and its own deadline.

I kept everything in a messy spreadsheet and twenty open tabs. I still missed deadlines. Missing a scholarship deadline is not like missing a sale. The money is simply gone, and you wait a whole year for the next chance.

Who it is for

Lodestar is meant for the student checking a scholarship page between classes, on a phone, trying to work out whether it is even open to them.

A note on the data

The scholarships here are real and open to international or all nationality students, gathered from public listings. The amounts and deadlines shown are representative. Always confirm the current details on each provider's own page before you apply.

Scholarship list last compiled: July 31, 2026. Most deadlines are stored as an offset from today so the demo stays evergreen, not as fixed calendar dates. The one exception is the Lounge Lizard Web Design Scholarship, whose real Fall 2026 deadline (October 4, 2026) was checked against its official page on September 28, 2026.

Why this is a website and not just a spreadsheet

Lodestar itself, the entire tool you are using right now, is my submission for the . I could have kept my scholarship tracker as a private spreadsheet. Instead, I chose to build the tool I genuinely needed and let it double as the design portfolio piece this scholarship asks for.

Colophon

Typefaces
Fraunces for headings, chosen for its warmth and slightly old-fashioned optical sizing. Inter for body text and interface labels, chosen for how evenly it reads at small sizes. JetBrains Mono for numbers, dates, and data, chosen so figures always line up and never get mistaken for prose.
Built with
Plain HTML, CSS, and JavaScript. No framework, no build step, no external charting library. The Constellation view and every chart on this site are hand-drawn on a canvas or in SVG. .

What Lodestar actually does

01

Shows only what you can win

Every scholarship listed here accepts international students, or does not restrict by nationality at all. Nothing here is a dead end before you start.

02

Puts deadlines on one line

The horizon lays out everything you are tracking by days remaining, so you can see what is due next without opening anything.

03

Walks each application with you

Open a scholarship and there is a checklist, a countdown, and a single button for marking it submitted.

04

Keeps your progress in one board

Save what fits, then move each one from not started to submitted as you go. Your board remembers where you left off.

05

Remembers who you asked, and when

Recommenders, essay angles, and a snippet library, so a paragraph written once can be reused on the next scholarship that asks a similar question.

06

Gives you honest numbers, not vibes

How many applications a given win rate actually needs, which one pays most per hour of work, and a warning when a deadline is nearer than the draft is ready for.

How this actually got built

Not a marketing timeline. This is a genuine account of how Lodestar grew, phase by phase, including the parts that had to be corrected along the way.

Phase one, the core tool

Home, Explore, Compare, Constellation, and My Applications, built around 38 real scholarships. The first working version already had filters, a Kanban board, and a deadline horizon, because a tracker that only shows a list isn't much of a tracker.

Phase two, making it trustworthy

An accessibility pass across every screen: contrast checked in both themes, focus order fixed, screen reader labels added where cards had none. A security pass caught and closed an XSS gap in the search input before it ever reached anyone. Dark mode, a high-contrast mode, and a reduced-motion path followed.

Phase three, the design system

The page you were just looking at. Every contrast ratio on it is computed live in your browser, not asserted as a claim, because a design system that only describes itself isn't proof of anything.

Phase four, the features that changed how it gets used

Time-crunch warnings, a value-per-hour sort, recommender tracking with lead-time nudges, an essay snippet library that carries across scholarships sharing a theme, and an honest calculator for how many applications a given win rate actually needs. The goal throughout was real usefulness, not just a longer feature list.

Phase five, the parts that got caught late

A font mismatch in one paragraph, spotted by an actual reader, not a test. A "restore backup" button that only appeared once the board already had scholarships on it, which is exactly backwards for someone setting up on a new device. A keyboard shortcut that stopped responding after the command palette closed, traced to focus getting stuck rather than returning to the page. Each one fixed and re-verified once found.

Phase six, letting people track what is not in the list

Not every scholarship worth applying to is one of the 38 curated here. Custom scholarships came with the same status tracking as everything else, which then surfaced a quieter problem: three separate warning systems, the browser tab badge, the deadline pile-up notice, and the past-deadline reminder, had each been written to check only the curated list. A custom scholarship closing tomorrow would sit there unflagged. One shared function fixed all three at once, which is usually a sign the first version of something was three almost-identical pieces of logic instead of one.

Phase seven, checking whether the explanations kept up

A product that keeps growing tends to leave its own descriptions of itself behind. The onboarding tour still did not mention the command palette, weeks after it was built. The About page's list of what this does described the first version, not the one with recommender tracking and honest odds math. The design system's own component showcase was displaying an old deadline pill without the shape icons added later for colorblind users, on the one page whose entire purpose is showing the current state of the design honestly. None of these were breaking anything. They were just quietly out of date, which is its own kind of bug.

Phase eight, making the dates tell the truth

Every deadline here was stored as a number of days from today, which keeps a demo evergreen but quietly lies about the one date that matters most on this page: the Lounge Lizard deadline. It now uses the real Fall 2026 date from the official page, and once that date passes the site says the cycle has closed instead of counting into negative days. The same pass caught a mobile layout bug where the hero text sat flush against the screen edge, and an invisible toolbar that was reserving a blank band above the Explore results.

What this page is for

Software is not a straight line from idea to finished product. It is a lot of small corrections. This page exists so that process is visible instead of hidden behind a polished final screenshot.
